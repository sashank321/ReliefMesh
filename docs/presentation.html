HOT ALLOCATION PATH: SINGLE-DOCUMENT OCC

• Uses atomic conditional update: updateOne({ _id, __v, availableQuantity: { $gte: qty } }, { $inc: { __v: 1 } })
• WiredTiger document-level lock: zero distributed lock waits, zero deadlock risk, sub-5ms predicate check.
• Contention surfaces as cheap failed predicate (modifiedCount: 0) triggering instant jittered rematch.

CROSS-BOUNDARY: MULTI-DOCUMENT ACID TRANSACTIONS

• Reserved strictly for multi-entity lifecycle commits spanning separate collections.
• Atomically inserts active_mission record + locks resource_inventory allocation lease + appends audit_log.
• Eliminates inter-agency blame games: non-repudiable cryptographic logging across agency boundaries.

Slide 03 | System Architecture

System Architecture & Dual-Branch Telemetry Ingestion

High-throughput time-series streaming combined with reactive spatial barrier calculation

END-TO-END REACTIVE PIPELINE FLOW
1. Field Ingestion Layer Citizen SMS/Voice via Twilio → Whisper API → Structured Living Incident Doc (GeoJSON + Embeddings). IoT River Gauges → MQTT Gateway → Real-time raw telemetry stream.
2. Atlas Stream Processing (ASP Dual-Branch) Branch A writes thousands of measurements into sensor_telemetry time-series collection. Branch B runs $setWindowFields with $derivative (rate-of-rise) over 5-minute tumbling windows.
3. The Hydraulic Model Boundary (HEC-RAS / Hydro-ML) When rate-of-rise breaches 25 cm/min threshold → ASP emits alert to external Flood Model Sidecar. Sidecar computes 2D Digital Elevation Model (DEM) fluid flow and writes Polygon to hazard_perimeters.
4. Reactive Change Stream Daemon Change Stream with Pre/Post Images calculates polygon delta (newly flooded area). Evaluates $geoIntersects against active_missions route LineString → Flags compromised convoys.
GOTCHA #1: TIME SERIES DUAL-BRANCHING (ASP)

Internal Constraint: Time Series collections use columnar block compression. Measurements are stored in compressed buckets — NOT discrete document mutations.

-> TIME SERIES COLLECTIONS DO NOT EMIT CHANGE STREAMS.

The Dual-Branch Fix: ASP branches telemetry before storage: Branch A writes compressed historical series; Branch B fires operational threshold alerts.

GOTCHA #2: THE POLYGON FABRICATION BOUNDARY

The Physical Reality: A point gauge reading (water level at lat/long point) CANNOT magically produce a spatial flood polygon inside a database query. Inundation requires Digital Elevation Models (DEM) and fluid physics.

The Boundary: MongoDB ASP detects hydrological rise-rate change; external Flood-Model Sidecar (HEC-RAS / Hydro-ML) calculates predicted flood polygon geometry; MongoDB owns 2dsphere indexing and reactive invalidation.

Slide 05 | The Reactive Loop

The Reactive Loop — Delta-Scoped Invalidation

Oplog-backed change streams with pre/post-images, spatial delta diffing, and cold-start resync

DELTA-SCOPED INVALIDATION WITH PRE/POST-IMAGES
// 1. Enable Pre/Post-Images on Hazard Collection db.runCommand({ collMod: "hazard_perimeters", changeStreamPreAndPostImages: { enabled: true } }); // 2. Watch Change Stream with targeted polygon filter const stream = db.hazard_perimeters.watch( [{ $match: { operationType: { $in: ["insert", "update", "replace"] }, "updateDescription.updatedFields.polygon": { $exists: true } } }], { fullDocumentBeforeChange: "whenAvailable" } ); stream.on("change", async (change) => { const postPolygon = change.fullDocument.polygon; const prePolygon = change.fullDocumentBeforeChange?.polygon; // Calculate newly flooded delta area (postPolygon - prePolygon) const deltaArea = prePolygon ? turf.difference(postPolygon, prePolygon) : postPolygon; // Invalidate ONLY missions crossing the newly expanded flood area const compromised = await db.active_missions.find({ status: "in_transit", "route.geometry": { $geoIntersects: { $geometry: deltaArea } } }).toArray(); for (const m of compromised) { await db.active_missions.updateOne( { _id: m._id, __v: m.__v }, { $set: { status: "route_compromised", flaggedAt: new Date() }, $inc: { __v: 1 } } ); rerouteWorker.dispatch(m._id); // Trigger OSRM detour } });
STREAM CHECKPOINTING & COLD-START RECOVERY

Oplog-Backed Checkpoints: Workers store resumeToken (_id of change event) in stream_checkpoints. Reconnect uses .watch([], { resumeAfter: lastSavedToken }).

2. Checkpoints latest oplog cluster timestamp.

Slide 06 | Architecture Audit

Honest Architecture Audit — PostgreSQL vs. MongoDB Atlas

De-rigged trade-off matrix: Conceding road routing, auditing CAS parity, and establishing operational survival

Dimension PostgreSQL (+PostGIS / pgvector) + Debezium + Kafka MongoDB Atlas (8.1+) Architectural Verdict
Road Network Routing WINNER: Native pgRouting computes Dijkstra/A* shortest path directly in SQL. Externalized to OSRM sidecar. $graphLookup is inadequate for road graphs. Concession: MongoDB does not do road routing. OSRM owns road graphs; MongoDB owns spatial barriers.
Relational Integrity WINNER: Declarative foreign keys across normalized schemas with compile-time checks. Document model + schema validation via $and: [ { $jsonSchema }, { $expr } ]. PostgreSQL excels at fragmented tables; MongoDB excels at cohesive operational aggregates.
Single-Row CAS Contention PARITY: Under default READ COMMITTED, concurrent UPDATEs re-evaluate WHERE -> 0 rows. PARITY: Single-document CAS ($inc: { __v: 1 }) returns modifiedCount: 0. Honest Audit: Both engines handle single-row CAS with cheap failed predicates. Edge is the loop, not the CAS.
Reactive CDC Loop Requires external Debezium workers + Kafka cluster + replication slots to stream changes. WINNER: Native Resumable Change Streams backed by the oplog with pre/post-images. Core Differentiator: MongoDB eliminates Kafka and Debezium for this bounded loop without infrastructure sprawl.
Operational Control Plane 3 independent distributed systems to deploy, monitor, and sync (PostgreSQL + Debezium + Kafka). WINNER: 1 managed data control plane (Vector + Geo + Transactions + Streams). SURVIVAL FEATURE: Under diesel generator cuts and 80% packet loss, restarting 1 engine saves lives vs debugging 5.
